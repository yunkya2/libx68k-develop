# DOS/IOCS コールCSVフォーマット仕様

このドキュメントは、次の入力CSVのフォーマットを定義する。

- [libx68k/libdos/doscall.csv](libx68k/libdos/doscall.csv)
- [libx68k/libiocs/iocscall.csv](libx68k/libiocs/iocscall.csv)

## 共通ルール

- 文字コードはUTF-8とし、BOMの有無は問わない。
- CSVとして空の行は無視する。
- 各セルは解釈前に前後の空白を除去する。
- 未使用列は空文字にする。
- 戻り値型が空の行はdefine専用行とし、インライン関数、プロトタイプ、ライブラリ実装を生成しない。
- C型欄に `%` が含まれる場合は仮引数名の挿入位置として置換する。関数ポインタなど、名前を型の途中へ置く必要がある宣言に使用する。

## doscall.csv

### 列構成

| 列 | 内容 |
|---:|---|
| 0 | DOSコール番号 |
| 1 | API名 |
| 2 | 戻り値型と属性 |
| 3～26 | 引数1～8。各引数につき3列 |
| 27 | 説明 |

引数 `n`（1～8）の先頭列は `base = 3 + (n - 1) * 3` で求める。

| 列 | 内容 |
|---:|---|
| `base + 0` | スタック幅指定 |
| `base + 1` | C型、または定数値 |
| `base + 2` | C仮引数名 |

### DOSコール番号

DOSコール番号は、`0xff20` のように `0x` で始まる16進形式で記述する。

### API名の制御記号

| 記号 | 意味 |
|---|---|
| `#` | DOSコール番号マクロを生成しない |

### 戻り値型と属性

通常は `int`、`void`、ポインタ型などのC戻り値型を記述する。型を省略した場合はdefine専用行となる。

C戻り値型の先頭には次の属性を複数指定できる。

| 記号 | 意味 |
|---|---|
| `!` | 宣言に`__attribute__((noreturn))` 属性を付け、復帰処理を生成しない |
| `$` | DOSコールがABI上のcallee-savedレジスタを含む全レジスタを破壊する |
| `%` | 宣言に `__attribute__((const))` を付ける |

例:

```text
int
!void
$int
!$void
%int
```


### スタック幅指定

| 指定 | 意味 |
|---|---|
| `w` | DOSコール用スタックへ16bitワードとして積む |
| `l` | DOSコール用スタックへ32bitロングワードとして積む |
| `hb` | 値の下位8bitをワードの上位バイトとして積む |
| `b` | 値の下位8bitをワードの下位バイトとして積む |
| `c` | DOSコール用スタックへ16bit定数を積む |

`hb` の直後に `b` がある場合は、2つの値を1ワードへ合成する。単独の `hb` は下位バイトを0、単独の `b` は上位バイトを0として積む。

### ORマスク付き幅指定

`w|<整数>` または `l|<整数>` と記述すると、引数へマスクをORしてから積む。

```text
w|0x0100
l|0x80000000
```

- マスクはPythonの `int(text, 0)` で解釈できる表記にする。
- `w` のマスクは16bit、`l` のマスクは32bitに制限される。
- `hb`、`b`、`c` にはORマスクを指定できない。

### 定数引数

スタック幅が `c` の場合は、その引数を16bit定数として扱う。定数値はC型欄に記述する。

- 値はPythonの `int(text, 0)` で解釈できる形式にする。
- 値の範囲は `-0x8000`～`0xffff` とする。
- 範囲外の値を16bitへ切り詰める処理は行わず、生成時にエラーとする。
- `c` 以外の幅では、C型欄が数値でも定数引数として扱わない。
- Cプロトタイプの仮引数には含まれない。
- ORマスクは指定できない。

非定数引数はC呼び出し側では1引数につき32bitのスタックスロットを使用し、生成関数内でDOSコールが要求する幅へ積み直される。

## iocscall.csv

### 列構成

| 列 | 内容 |
|---:|---|
| 0 | IOCSコール番号 |
| 1 | API名 |
| 2 | 戻り値型、属性、戻り値レジスタ |
| 3～20 | 引数1～6。各引数につき3列 |
| 21 | 説明 |

引数 `n`（1～6）の先頭列は `base = 3 + (n - 1) * 3` で求める。

| 列 | 内容 |
|---:|---|
| `base + 0` | 入力レジスタ、部分レジスタ、または出力レジスタ指定 |
| `base + 1` | C型、または定数値 |
| `base + 2` | C仮引数名 |

途中の引数ブロック3列がすべて空の場合、それ以降の引数解析を終了する。

### IOCSコール番号

コール番号はPythonの `int(text, 0)` で解釈できる形式で記述する。通常は `0x00`～`0xff` を使用する。

インライン関数では、`0x80`以上の番号を8bit符号付き即値へ変換して `d0` に設定する。

### API名の制御記号

| 記号 | 意味 |
|---|---|
| `%` | 番号マクロの値にコール番号ではなく、引数欄で最初に見つかった定数値を使う |
| `#` | IOCSコール番号マクロを生成しない |

IOCSのAPI名では `#` と `%` を併用できる。

### 戻り値型と戻り値レジスタ

通常は `int`、`void`、ポインタ型などのC戻り値型を記述する。型を省略した場合はdefine専用行となる。

C戻り値型の先頭には次の属性を複数指定できる。

| 記号 | 意味 |
|---|---|
| `!` | 宣言に`__attribute__((noreturn))` 属性を付け、復帰処理を生成しない |
| `%` | 宣言に `__attribute__((const))` を付ける |

通常はIOCSコール実行後の `d0` レジスタの値がC関数の戻り値となるが、`型=<レジスタ>` と記述すると、`d0` の代わりに指定レジスタの値が戻り値となる。

```text
int=d2
void *=a1
```

- 戻り値レジスタには `d0`～`d7` または `a0`～`a7` を指定できる。
- レジスタ名の大文字・小文字は区別しない。
- `=` の前後に空白を入れてもよい。
- 指定したレジスタがcallee-savedの場合、ライブラリ実装は値を `d0` へ移してから元のレジスタを復帰する。

### 入力レジスタ指定

通常の引数は次のレジスタ指定を使用する。

| 指定 | 意味 |
|---|---|
| `d0`～`d7` | データレジスタ全体 |
| `a0`～`a7` | アドレスレジスタ全体 |
| `dNh` | データレジスタの上位16bit |
| `dNl` | データレジスタの下位16bit |
| `dNhb` | データレジスタのbit 15～8 |
| `dNb` | データレジスタのbit 7～0 |

アドレスレジスタには `h`、`l`、`hb`、`b` の部分指定を使用できない。

同じ基本レジスタについて、全体指定と部分指定は併用できない。同じ部分を複数指定することもできない。

通常の入力引数ではC型と仮引数名を必ず記述する。どちらかが空の場合は生成時にエラーとなる。

### 定数入力

C型欄が整数として解釈できる場合、その引数はレジスタへ設定する定数となる。

- Cプロトタイプの仮引数には含まれない。
- データレジスタとアドレスレジスタのどちらにも指定できる。
- `d1` の定数は、IOCSコール番号を `d0` へ設定する直前までロードを遅延する場合がある。

### 出力ポインタ引数

レジスタ欄を `=<レジスタ>` とすると、その引数はIOCSコールへ渡す入力ではなく、実行結果を受け取るポインタになる。

```text
=d2,void *,id_out
```

- 出力レジスタには `d0`～`d7` または `a0`～`a7` を指定する。
- C型欄には `*` を含むポインタ型が必要となる。
- 仮引数名を必ず記述する。
- Cプロトタイプには通常のポインタ引数として含まれる。
- trap前には指定レジスタへポインタ値をロードしない。
- trap後に指定レジスタの32bit値をポインタ先へ書き込む。
- 戻り値型の `型=<レジスタ>` と併用できる。
- 同じ結果レジスタを通常の入力引数にも指定できる。

複数の出力ポインタがスタック上で連続する場合、ライブラリ実装はABI上で破壊可能なアドレスレジスタへ `moveml` でまとめてロードする。

- GCC ABIでは通常 `a0/a1` を使用する。
- XC ABIでは通常 `a0/a1/a2` を使用する。
- 結果値が入っているアドレスレジスタは、書き戻すまで作業レジスタとして使用しない。
- 利用可能なレジスタ数を超える場合は複数グループに分ける。
- ポインタがスタック上で非連続の場合は個別にロードする。
- caller-savedアドレスレジスタをすべて結果が占有する場合は、未使用のcallee-savedレジスタを1本退避して使用する。

## 生成対象のまとめ

| 行の指定 | インライン | プロトタイプ | ライブラリ | 番号マクロ |
|---|:---:|:---:|:---:|:---:|
| 通常 | ○ | ○ | ○ | ○ |
| API名先頭 `#` | ○ | ○ | ○ | × |
| 戻り値型が空 | × | × | × | ○ |
| API番号先頭 `#` | × | × | × | × |

IOCSのAPI名先頭 `%` は通常行と同様に各コードを生成するが、番号マクロの値だけを最初の定数引数へ変更する。

## overrideファイル

DOSとIOCSのoverrideは同じ書式を使用する。配置先は次のとおり。

- DOS: `libx68k/libdos/overrides/`
- IOCS: `libx68k/libiocs/overrides/`

overrideファイルでは次のセクションを使用できる。

- `[lib]`: ライブラリ用アセンブリ実装
- `[inline]`: ABIに依存しないインライン関数実装

`[lib]` 内では、DOSとIOCSのどちらもABI別の行頭指定を使用できる。

- 無印の行: 両ABIで出力
- `@gcc `: `--abi gcc` の場合だけ、接頭辞を除いて出力
- `@xc `: `--abi xc` の場合だけ、接頭辞を除いて出力

`@gcc` / `@xc` は `[inline]` では解釈されない。

overrideは、ファイル名またはファイル名末尾がAPI名、API名から先頭の `_` を除いた名前、もしくはそれらをファイル名用に正規化した名前と一致するものを検索する。大文字・小文字は区別しない。

ABIごとのcallee-savedレジスタは次のとおり。

- GCC ABI: `d2-d7/a2-a6`
- XC ABI: `d3-d7/a3-a6`
